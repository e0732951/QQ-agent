# 今日塔罗（jy-tarot）插件 v3.0.0 · 安装说明（**给 AI/Agent 看**）

> 这份是给**替你装插件的 AI**看的：照着做即可，每条都写了**为什么**和**怎么验证**。
> 另有一份 `安装必读-给人看.txt` 是给人类看的白话版。

---

## 0. 一句话

把 `jy-tarot/` 整个文件夹（**含 `assets/` 与 `data/` 两个目录**）丢进宿主程序的 `plugins/` 目录里，
启用它，**大退重启**。它**硬依赖「指令前置」插件**（`command.dispatch`），
并且出图依赖**宿主自身的渲染窗口（Electron）**。

---

## 1. 装之前必须确认的三件事

### ① 宿主程序是什么

这是 **QQ-Agent（SnowLuma）** 的插件。项目根目录里必须有 `src/` 和 `plugins/`：

```
<项目根>/
  src/            ← 宿主核心（**不要动**）
  plugins/        ← 插件都放这里
  data/           ← 配置与数据
```

**验证**：`<项目根>/src/plugin-loader.js` 存在。

### ② 必须已装 **「指令前置」（jy-command-gateway）**，且处于启用状态

`plugin.json` 里写的是**硬依赖**：

```json
"requires": ["command.dispatch"]
```

**验证**：`设置 → 插件` 里能找到「指令前置」，且状态是**已启用**。

> ⚠️ 缺它 ⇒ 本插件**完全不激活**（不是降级，是"依赖未就绪"）。
> 因为四条指令全靠它识别和分发；插件代码里**不直接调用** `command.dispatch`（见 §4）。

### ③ 必须是**能开窗口的 Electron 宿主**（出图用）

本插件出图不是用 canvas 库，而是**借用宿主自己的 `BrowserWindow`** 渲染一张本地 HTML：

```js
// index.js  getElectron()
const req = createRequire(pathToFileURL(path.join(PLUGIN_DIR, 'index.js')).href);
return req('electron');
```

- 正常桌面版 ⇒ 能出图
- 纯 Node / 无窗口宿主 ⇒ **降级为文字回执**（不会崩）
- 而且它复用**同一个**渲染窗口、**永不销毁**，并挂在 `globalThis` 上（热重载后仍是同一个）

> ⚠️ 有一个真实边界（代码里已写明）：**如果那个渲染窗口被外部关掉了，本进程不能再新建**
> ⇒ 之后每次渲染都会降级为文字。想恢复只能**大退重启**。

## 2. 安装步骤

### 步骤 1：放文件

把 `jy-tarot/` **整个文件夹**复制到：

```
<项目根>/plugins/jy-tarot/
```

**目录结构必须是**（缺一不可）：

```
<项目根>/plugins/jy-tarot/
  index.js              ← 插件主进程（4 条指令 / 抽三张牌 / 记账 / 渲染 / 发图）
  plugin.json           ← 清单（4 条指令 / 依赖 / 配置项）
  settings-ui.js        ← 设置页（改指令词）
  lib/
    tarot-page.mjs      ← ★ index.js 会 import 它（渲染页模板），**不能少**
  data/                 ← ★ 牌面数据（5 个 json）
    data-major.json       大阿卡纳（22 张）
    data-minor.json       小阿卡纳（20 张）
    data-court.json       宫廷牌（16 张）★ v3 新增
    data-luck.json        签位（凶/末吉/吉/中吉/大吉）
    data-combo.json       组合建议模板
  assets/               ← ★ 塔罗牌图片（121 张 jpg，约 24.7 MB）★ v3 新增 32 张宫廷牌
```

⚠️ **绝对不要**只复制 `index.js` 和 `plugin.json` —— 少了 `lib/` 会在加载期直接报错；
少了 `data/` 或 `assets/` 会在抽牌时抛"读取失败"。
⚠️ **不要**把里面的文件直接倒进 `plugins/`，要保持 `plugins/jy-tarot/` 这一层。

> 📌 **包里没有的东西**（开发期产物，被有意排除；缺了不影响任何功能）：
> `_selftest.mjs`（开发期自测）、`_e2e*.mjs`（端到端出图测试）、`tarot.json`（v1 遗留数据表）、
> 任何审计报告与备份目录。

### 步骤 2：启用它

`enabledByDefault: false` ⇒ **装完默认是关的**，必须手动开。

- **A（推荐）**：宿主里 → `设置 → 插件` → 找到 **今日塔罗** → 打开开关
- **B**：编辑 `<项目根>/data/config.json`，在 `skills` 下加：

```json
"jy-tarot": { "enabled": true }
```

> ⚠️ 改 `config.json` 前**先备份**，并确保程序是关闭的（否则会被内存里的配置覆盖回去）。

### 步骤 3：**大退重启**

**必须完全退出程序再打开**（不是最小化、不是刷新页面）。
原因：插件运行在宿主的 **Node 主进程**里，只有重启才会重新加载。

### 步骤 4：确认指令前缀

指令走「指令前置」的分发，**前缀默认是 `/`**（可在指令前置的设置里改）。

⇒ 在群里发 `/今日塔罗`（或者你改过的那个前缀 + `今日塔罗`）。

## 3. 装完怎么验证（**4 条**）

### 验证 1：插件被加载

`设置 → 插件` 里 **今日塔罗** 显示为「已启用」，且**没有**"依赖未就绪"。
`available()` 会**逐张核对 121 张素材**：少一张都会显示"素材缺失 N 张（如 …）"，而不是等你抽牌才发现。

### 验证 2：指令被识别（不要求出图成功）

在群里发 `/今日塔罗`：

- ✅ 有回执（文字或图片）⇒ 指令链通了
- ❌ 完全没反应 ⇒ 回 §1② 查指令前置、或 §2 步骤 4 查前缀

### 验证 3：能出图（**这条最关键**）

`/今日塔罗` 的回复**是一张图片**，且图上是**三张牌**（主题 / 事件 / 宫廷）。

- 出图成功 ⇒ Electron 渲染正常
- 出的是**文字回执** ⇒ 渲染失败，已被降级。排查顺序：
  1. 程序是不是桌面版、有没有窗口
  2. 之前是不是把渲染窗口手动关掉过（关过就只能大退重启恢复）
  3. 看宿主日志里有没有本插件的 `warn`（渲染超时默认 20 秒）

### 验证 4：抽签解读依赖顺序

1. 先 `/今日塔罗` ⇒ 出图（三张牌）
2. 再 `/抽签解读` ⇒ 出另一张图（签位 + 最终建议 + **宫廷指引**）

如果第 2 步只回复"抽取塔罗后才可抽签解读哦" ⇒ 说明当日塔罗没记上（见 §6 数据位置）。

## 4. 指令与依赖归属（**给排障用**）

### 它**提供**的（4 条指令，全部 `permission: 0` 即所有人可用）

| 指令词 | 能力名 | 干什么 | 超时 |
|---|---|---|---|
| `今日塔罗` | `command.tarot-today` | 抽大阿卡纳（主题）+ 小阿卡纳（事件）+ 宫廷牌（另一维度）各一张、判正逆位、合成图发会话。**每人每天一次**；重复发重发同三张 | 120 s |
| `抽签解读` | `command.tarot-luck` | 在今日塔罗基础上抽一支签（凶/末吉/吉/中吉/大吉各 20%），与当日牌面组合成建议，并在建议末尾附一段**宫廷指引**，出图。**必须先抽过今日塔罗** | 120 s |
| `测塔罗` | `command.tarot-test` | 内部测试：不记账、纯随机、可指定大/小/宫廷与正逆位。**仅测试白名单** | 120 s |
| `测抽签` | `command.tarot-luck-test` | 内部测试：指定签位出图。**仅测试白名单** | 120 s |

**这些指令由「指令前置」分发**（`plugin.json` 的 `commands[]` 声明 + `requires: ["command.dispatch"]`）。

> ⚠️ **别误判**：本插件在 `requires` 里写了 `command.dispatch`，但**代码里一次都没调用它** ——
> 这是**故意**的，表达的是"我把指令挂在指令前置上"。靠 `commands[]` 声明 + 网关发现来分发。

**测试通道的参数语法**（v3 新增宫廷牌）：

```
/测塔罗                          三张全随机
/测塔罗 大 15 逆                 大阿卡纳定死（0-21）
/测塔罗 小 07 正                 小阿卡纳定死（01-20）
/测塔罗 宫 03 逆                 宫廷牌定死（01-16）
/测塔罗 宫 权杖王后 逆           宫廷牌按中文名（也认「权杖皇后」）
/测塔罗 大 15 逆 小 07 正 宫 03 逆   三张都定死
```

### 它**需要**的

| 名字 | 归属 | 用途 | 缺了会怎样 |
|---|---|---|---|
| `command.dispatch` | **指令前置插件** | 指令分发（声明式，不直接调用） | 🔴 **插件不激活** |
| `electron`（`require('electron')`） | **宿主运行时** | 用 `BrowserWindow` 渲染出图 | 🟢 降级为文字回执 |
| `node:fs` / `node:http` / `node:module` | Node 内建 | 读牌面数据与图片、起本地静态服务、`createRequire` 拿 electron | ——（自带） |

**它没有调用任何 `api.capability()`** —— 也就是说它**不依赖**记忆星图 / 星链 / ai.ask 等任何能力。

### 生命周期钩子（宿主会调）

| 导出 | 宿主何时调 |
|---|---|
| `setup(api)` | 加载 / 热重载 |
| `available()` | 宿主自检（返回 `{ok:true}`；素材缺一张就返回 `{ok:false, reason}`） |
| `activate()` / `deactivate()` | 启用 / 停用（渲染窗口跨实例复用，不销毁） |
| `providers` | 4 条指令的能力表 |

## 6. 配置与数据写在哪

**配置**：`<项目根>/data/config.json` → `skills.jy-tarot`，共 **4 项**：

| 键 | 默认 | 含义 |
|---|---|---|
| `dailyLimit` | `1` | **每人每天可抽几次**（调大就能一天多抽） |
| `testAllowList` | `""` | **测试白名单**（填 QQ 号，逗号/换行分隔）。**默认空 = 谁都调不了「测塔罗」「测抽签」** |
| `testDenyText` | `这条是内部测试指令，你不在测试名单里。` | 不在白名单时的回执文案 |
| `needTarotText` | `抽取塔罗后才可抽签解读哦` | 没抽过塔罗就发"抽签解读"时的提示 |

**数据**：`<项目根>/data/command_data/jy-tarot/`

```
draws.json              谁哪天抽了大/小/宫廷哪三张、正逆位（记账 + history）
test-draws.json         测试通道的临时账本（30 分钟过期；与正式账本**分开**）
out/                    生成的图片缓存（tarot-<时间戳>-<随机>.png，24 小时后自动清理）
```

## 7. 升级 / 卸载

**升级（v2 → v3）**：把 `plugins/jy-tarot/` 整个替换成新版本
（**`lib/` `data/` `assets/` 要一起换**）⇒ **大退重启**。

> ⚠️ **v3 的账本迁移**：v2 的记录没有宫廷牌字段（`court`），v3 一律判为"今天没抽过"
> ⇒ 升级当天，那个人可以重新抽一次（会得到三张牌）。`seq` 计数保留，不会让所有人都跳回同一组牌。
> 跨天时本来就会清空，所以这只影响"升级当天已经抽过"的人。

**卸载**：删掉 `plugins/jy-tarot/` 整个文件夹，或在宿主里关掉开关。
残留项（可选清理）：
- `data/config.json` 里 `skills.jy-tarot` 那一段
- `data/command_data/jy-tarot/` 整个目录（记账 + 图片缓存）

## 8. 排障速查

| 症状 | 最可能的原因 | 怎么办 |
|---|---|---|
| 插件列表里显示"**依赖未就绪**" | 指令前置没装 / 没启用 | 回 §1② |
| 发 `/今日塔罗` **完全没反应** | ①指令前置没启用 ②指令前缀不是 `/` ③插件没开 | 依次查 §1②、§2 步骤 4、§2 步骤 2 |
| 显示"素材缺失 N 张" | `assets/` 没换全（v3 新增 32 张宫廷牌） | 按 §2 步骤 1 的目录结构重放 |
| 加载就报错 `Cannot find module ... tarot-page` | **`lib/` 没带上** | 同上 |
| 抽牌时报"读取失败" | **`data/` 缺 `data-court.json`** 或 `assets/` 没带 | 同上 |
| 只回**文字**不出图 | Electron 渲染失败（窗口被关过 / 非桌面版 / 超时 20 s） | 大退重启；看宿主日志里的 warn |
| 图里只有两张牌 | 装的是 **v2** 的 `lib/tarot-page.mjs`（被漏换） | 整包替换，别只换 `index.js` |
| 「测塔罗」没反应 | 测试白名单是空的（默认就是空的） | 在插件设置里填 QQ 号 |
| 「测塔罗 宫 权杖骑士」回"参数看不懂" | 装的是 v2 的 `index.js` | 整包替换 |
| 「抽签解读」说"抽取塔罗后才可抽签解读哦" | 当日还没抽塔罗（或换了人 / 刚升级被迁移） | 先发 `/今日塔罗` |
| 抽过了想再抽，它说今天抽过了 | `dailyLimit` 默认 1 | 调大每日上限 |
| 改完设置不生效 | 热重载可能没接管 | **大退重启** |

## 9. 已知限制（**别当 bug 报**）

- **牌库不是完整 78 张**：大阿卡纳 22 张齐全；小阿卡纳只有 **20 张**（4 花色 × Ace/3/6/9/10）；
  宫廷牌 **16 张**（4 花色 × 侍从/骑士/王后/国王）。其余点数与阿斯牌以外的牌**不在牌库里**。
- **每人每天一次**（`dailyLimit` 可调，最大 9）。重复发会把今天那三张**再发一次**，不会重抽。
- **当天结果恒定**：同一个人同一天抽到的三张牌不会变（种子由"本地日期 + QQ + 第 n 次"派生）。
  这是故意的 —— 否则反复发 `/抽签解读` 就能刷出"大吉"。
- **图一是 1500 CSS 宽**（输出约 2250×1200 像素，2.5 MB 左右），比 v2 宽；
  **图二仍是 1180 CSS 宽**（约 1770×1060），版面与 v2 完全一致。
- 图片是**本地渲染 + 本地临时文件**发送，出图耗时约 0.3–1 秒/张（串行排队，最长排队 25 秒）。
